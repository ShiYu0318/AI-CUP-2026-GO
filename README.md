# AI CUP 2026 秋季賽－圍棋棋力與風格預測競賽

- [競賽一：從圍棋棋譜集辨識玩家](https://www.aidea-web.tw/topic/dc0b799e-690f-4e84-a597-93e68d8ba688)
- [競賽二：從圍棋棋譜預測玩家棋力等級](https://www.aidea-web.tw/topic/8c36af8c-2c70-497f-a862-6fb81a53a403?focus=intro)

兩個子題共用同一份訓練集：100 萬局匿名人類圍棋棋譜，10 個棋力等級各 10 萬局。

| | 競賽一 | 競賽二 |
| --- | --- | --- |
| 任務 | 開放集合檢索（從 400 人候選庫找出是誰，交 Top-5） | 10 類有序分類（D/C/B/A/1D–6D） |
| 評分 | `exp(-(r-1))`，r 為正解名次 | 完全正確 1、相鄰一級 `exp(-1)`、其餘 0 |
| 官方 baseline | 0.2845 | 0.4631 |

## 設計原則

這個 repo 的所有程式都圍繞三條原則，而三條都來自對官方 baseline 的實測缺陷：

1. **驗證以「玩家」為切分單位，不是「棋局」。**
   官方 tutorial 把 100 萬局 shuffle 後取前 10 萬局當驗證集，實測驗證集的
   7,463 位玩家有 **100.00%** 同時出現在訓練集裡。真實測試集的玩家是完全未見的，
   所以那個驗證分數系統性高估泛化能力。

2. **指標以「題目」為單位，不是「單局」。**
   官方每題給 5～20 局。實測單局 top-1 只有 15.5%，但題目層級聚合後可達 0.35——
   分數的主體來自聚合，用單局 accuracy 選模型會選錯。

3. **解碼對齊評分函數，不用 argmax。**
   競賽二的相鄰等級有 `exp(-1)` 部分分，`argmax` 完全不知道這件事。
   改用期望分數解碼 `argmax_c Σ_k p_k · S(c,k)` 是三行程式碼的免費增益。

## 快速開始

```bash
# 1. 下載官方訓練集（1.3 GB，走官方 Releases）
#    https://github.com/AILAB-NDHU/aicup2026-go-dataset/releases
tar xf aicup2026_go_training.tar.xz        # 解出 training/

# 2. 一次算好全部 100 萬局的手工特徵（10 核約 9 分鐘，產出 644 MB）
python3 scripts/build_feature_store.py --nproc 10

# 3. 跑 baseline，取得 player-disjoint、題目層級、官方公式的分數
python3 scripts/run_baselines.py

# 4. 多任務深度模型（建議在有 GPU 的機器上）
python3 scripts/train.py --device cuda --width 128 --blocks 10 --steps 20000
python3 scripts/train.py --smoke            # 只驗證流程能跑通

# 測試
python3 -m pytest tests/ -q
```

## 程式庫結構

```

├── __init__.py      LEVELS 等常數（等級順序決定「相鄰」的定義，很重要）
├── scoring.py       官方評分函數、期望分數解碼、溫度校準、檢索指標
├── goboard.py       SGF 解析 + 棋盤（提子、氣）。不依賴 sgfmill
├── data.py          metadata 快取、player-disjoint 切分
├── benchmark.py     題目層級基準（完整複製官方協定，支援多種候選庫等級組成）
├── features.py      手工特徵 168 維（行為統計 / 死活統計 / 局面品質 / 位置分布）
├── planes.py        深度模型的 34 層盤面表徵
├── baselines.py     手工特徵的兩個子題 baseline
├── dataset.py       PyTorch 資料集、P×K 取樣器、8 相位對稱增強
├── losses.py        指數 soft label、CORN、sub-center ArcFace、batch-hard triplet
├── nets.py          共用 backbone 的多任務網路（GeM + BN-Neck + attention pooling）
└── submission.py    提交檔產生與官方格式驗證

scripts/
├── build_feature_store.py   一次算好 100 萬局特徵
├── run_baselines.py         離線評估（67 天沒有 leaderboard 期間的儀表板）
└── train.py                 多任務訓練
```

## 實測發現

全部在 player-disjoint 切分、題目層級、官方評分公式、多個 seed 上量測。
重現方式：`python3 scripts/run_baselines.py`、`scripts/eval_player_postprocess.py`、
`scripts/eval_rank_prior.py`。

### 目前的離線分數

| 子題 | 官方 baseline | 本專案（手工特徵，零深度學習） |
|---|---:|---:|
| 競賽一 玩家辨識 | 0.2845 | **0.6720**（400 人候選庫，等級均勻） |
| 競賽二 棋力預測 | 0.4631 | 0.3973（尚未超過，需要深度模型） |

競賽一依候選庫等級組成的區間：`kyu_only` 0.7814 / `natural` 0.6686 /
`uniform` 0.6490 / `skewed` 0.6198 / `dan_only` 0.5883。
**級位比段位好辨識 1.33 倍** —— 弱者的下法更個人化。

### 兩個子題的非對稱性

同一套手工特徵，在兩個子題上的表現完全相反：

| | 競賽一 玩家辨識 | 競賽二 棋力預測 |
|---|---:|---:|
| 官方 CNN baseline | 0.2845 | 0.4631 |
| 手工特徵 | **0.6720**（2.36 倍） | 0.3973（0.86 倍） |

解釋：**身分**編碼在統計習慣裡（應手距離、脫先頻率、死活處理方式），
手工統計抓得準；**棋力**編碼在局面判斷的品質裡，統計量抓不到「好壞」，
必須真的理解盤面。

→ 競賽一可以用便宜的方法走很遠；競賽二非投入深度模型或引擎特徵不可。
（把訓練資料從 20 萬放大到 78 萬局：0.3703 → 0.3804；再把模型容量加倍：0.3851。
總共 +0.015 而訓練時間變 6.9 倍，天花板很明確。）

### 最強的單一棋力訊號：愚形

針對「統計量抓不到局面判斷品質」這個瓶頸，設計了一組**不需要圍棋引擎**的品質特徵。
量測各特徵與棋力索引（D=0 … 6D=9）的相關係數：

| 特徵 | 相關係數 | 說明 |
|---|---:|---|
| **`empty_triangle`** | **−0.964** | 愚形：自己三子佔 2×2 的三點、第四點空。圍棋公認的壞形 |
| `abandon_atari` | +0.925 | 被打吃時果斷棄子；弱者硬救反而擴大損失 |
| `atari_given_rate` | +0.917 | 終局時對手處於打吃的棋串數 |
| `contact_early` | −0.680 | 開局 30 手內的貼身接觸比例 |
| `wasted_fill` | −0.674 | 官子把子下進自己已包圍的空點 |

愚形在 10 個等級上幾乎完美單調遞減（0.1465 → 0.1138），而且只需檢查 2×2 方塊。

把這 7 個品質特徵加進去（161 維 → 168 維）的實測效果：

| 子題 | 161 維 | 168 維 | 差異 |
|---|---:|---:|---:|
| 競賽二 | 0.3866 | **0.3973** | +0.0107 |
| 競賽一 | 0.6632 | **0.6720** | +0.0088 |

**教訓：單一特徵的強相關係數，不等於加進模型後的大幅提升。**
既有特徵已間接捕捉了大部分訊號，且題目層級聚合會稀釋單局的區辨力提升。
這指向一個具體建議：**棋力的訊號高度集中在局部棋形的好壞**，
深度模型值得加一個「棋形品質」的輔助 head，把這個已知的強訊號變成監督訊號。

新增特徵後可用 `python3 scripts/feature_signal_report.py` 逐一檢視訊號強度。

### 玩家辨識靠的是開局選點

`scripts/feature_signal_report.py` 對每個特徵算「玩家間變異 / 玩家內變異」，
結果完全可解讀：

| 特徵 | 盤上位置 | 區辨力 |
|---|---|---:|
| `open_cell27` | **星位 4-4** | **0.695** |
| `first_line` | 首手離邊距離 | 0.515 |
| `open_cell20` | **小目 3-4** | 0.419 |
| `open_cell54` | 天元 | 0.298 |

**最強的身分特徵就是「這個人開局愛下星位還是小目」。**
這與 NeurIPS 2021 behavioral stylometry 論文的結論一致，
也說明官方 baseline 跳過前 8 手是嚴重的設計缺陷。

反過來，競賽二的訊號極度冗餘——15 個以上的特徵與棋力的 |相關係數| > 0.96，
這解釋了為什麼新增 7 個強特徵只換到 +0.0107。

### 有效的改動

| 改動 | 增益 |
|---|---:|
| 聚合順序：單局標準化 → 單局 L2 → 平均 → 再 L2 | **+0.2604** |
| 死活特徵族（提子 / 氣 / 打吃 / 棋串數） | +0.0416 |
| logmean 取代 mean 聚合（競賽二） | +0.0301 |
| 期望分數解碼 + 溫度校準（競賽二） | +0.0166 |

### 實測無效或有害的改動

這些都是從 Kaggle 個體辨識競賽的金牌解法借來的「公認有效」技巧，
在本任務上**四條全部沒有轉移**：

| 技巧 | 實測 | 為什麼不轉移 |
|---|---|---|
| k-reciprocal re-ranking | 0.6490 → **0.4810** | 它靠 gallery 每個身分有多個條目互為近鄰；本任務是 1-對-1 匹配 |
| α-Query Expansion | 0.6490 → 0.6425 | 同上，鄰域結構太弱 |
| 棋力先驗重加權候選庫 | 中位 +0.0027（雜訊 ±0.013） | embedding 本身已隱含棋力資訊 |
| 多視角 embedding 拼接 | 0.6452 → 0.6457 | 拆分讓每個子 template 樣本減半、更吵 |

**啟示**：不要因為某個技巧在別的競賽「公認有效」就採用。
先問「它依賴的結構在這個任務裡存在嗎」，再到本地基準上實測。

## 官方資料集規格（摘自 [aicup2026-go-dataset](https://github.com/AILAB-NDHU/aicup2026-go-dataset)）

訓練集走官方 Releases，不進本 repo：

```bash
# aicup2026_go_training.tar.xz  214 MB，解壓後約 1.3 GB
# SHA-256: 959ebc602b9638d665cb063a6269e0d5aef73956b77913e725763eb335ced94b
tar xf aicup2026_go_training.tar.xz     # 解出 training/
```

欄位 `player_id, game_id, rank, color, sgf_content`，10 檔各 100,000 列。

**最重要的一條規格**：

> `rank` 是該玩家**所有對局的眾數等級**，不是單局等級；同一玩家的每一列都相同。

這解釋了為什麼單局 top-1 只有 0.1687 —— 標籤在單局層級本來就帶噪聲，
一位標為 3D 的玩家，個別對局的實際強度會散佈在附近幾級。
**這也是為什麼「5–20 局聚合」才是分數的主體，而不是單局模型精度。**

其他官方保證（已對全部 100 萬局驗證）：

| 官方說法 | 實測 |
|---|---|
| 手數至少 100 | ✅ 最小值恰為 100 |
| 已排除機器人與系統帳號 | — |
| 不含自殺、打劫、疊子，主分支可完整重播 | ✅ 提子不變量測試通過 |
| 保留屬性僅 `SZ` 與 `B`/`W`/`AB`/`AW`/`AE` | ⚠️ **實測只出現 `SZ`/`B`/`W`**，`AB`/`AW`/`AE` 零次（無讓子局），parser 不需處理 |
| 「`sgf_content` 內含逗號，請用標準 CSV 解析器」 | ⚠️ **實測 100 萬列零逗號**。官方這句是防禦性寫法；仍建議用標準 parser，但不必為此特別處理 |

## 資料的兩個陷阱

**CSV 依執色排序。** 每個 `train_*.csv` 的第 0–49,999 列全是 `B`、
第 50,000–99,999 列全是 `W`，只有一個切換點。
`pd.read_csv(..., nrows=10000)` 會拿到 100% 執黑樣本而毫無警訊。
抽樣前務必先 shuffle，或明確跨越分界。
（回歸測試：`tests/test_data_and_benchmark.py::test_csv_rows_are_sorted_by_color`）

**`game_id` 只在單一等級檔內唯一。** 10 個檔案都各自從 `g_0000001` 起編，
跨檔會重複 10 次。任何以 `game_id` 當鍵的快取都必須加上等級前綴。

## 提交格式（錯一次就整份作廢）

兩個子題都要把 public 400 題與 private 400 題**串接成一份 800 列**的 CSV，
缺任一份即該次提交無效不計分。競賽一另有兩條死線：
Top-5 必須相異、且 `pub_` 題目只能填 `pub_p_` 開頭的玩家（跨池即無效）。

`aicup.submission` 把這些規則寫成會丟例外的驗證函數，驗證不過就不寫檔。

## 測試

```bash
python3 -m pytest tests/ -q
```

測試涵蓋官方評分公式的邊界（`D` 與 `6D` 各只有一個相鄰級）、
棋盤提子的不變量（盤上子數 + 被提子數 = 總手數，對真實棋譜驗證）、
切分的互斥性、基準是否符合官方協定、以及每一條會讓提交作廢的格式規則。
