# 玩家辨識（競賽一）

這個子題的核心是**少樣本的開放集合檢索**：候選人全是訓練集沒出現過的新面孔，
模型要學的不是「認得這 8,007 個人」，而是一個能把「同一個人的棋」拉近、「不同人的棋」推開的 embedding。
訓練時的身分只是手段，推論時丟掉分類頭，只留 embedding。

## 原題型：候選 100 盤、題目 5～20 盤、一對一

```
一盤棋 ─→ 手工特徵 1164 維（我方＋對手＋棋形雙視角，去掉全域落子位置）
          │
          ▼  度量學習 MLP ×8 seed（隱藏層 1024、Sub-center ArcFace＋batch-hard triplet）
       embedding（每個 seed 一段，各自 L2）
          │
          ├─ 候選池分類器：用候選人自己的 100 盤現場訓練 400 類邏輯迴歸
          ▼
   每題各盤的 log 機率平均 → Sinkhorn 全域指派（ε=0.05）→ Top-5
```

演進（本地模擬，題目層級、跨 5 種候選庫等級組成）：

| 步驟 | 關鍵 | 效果 |
|---|---|---|
| 手工特徵＋標準化→L2→平均→L2 的餘弦模板 | **零訓練**就遠超官方 baseline | 起點 |
| ＋開局順序（前 6 手的折疊 one-hot） | 最強的身分訊號是「愛下星位還是小目」 | +0.18 |
| ＋度量學習（MLP＋Sub-center ArcFace） | 筆電 GPU 1～2 分鐘 | +0.07 |
| ＋Sinkhorn 全域指派 | 題目與候選一對一，一位「長得像很多人」的候選不能同時當很多題的答案 | +0.05 |
| ＋逐手棋形特徵 | 手法偏好（接／尖／跳／飛）是個人簽名；8 分鐘的訓練換到最大的單步增益之一 | +0.026 |
| ＋候選池分類器 | 官方允許用候選池做校正；每人 100 盤足以訓練一個線性分類器 | +0.002，接近全對 |

**為什麼選 Sinkhorn 不選匈牙利算法**：在一對一還沒確認時，量了「假設被違反」的情境——
三成候選是干擾項、或兩成五的答案重複。匈牙利算法強制一對一，假設錯時 −0.096；
Sinkhorn 是軟性平衡，三種情境都不會變差。官方確認一對一之後，ε 調緊到在三種情境下仍為正的最小值附近。
而且因為 Top-5 的第 2～5 名也計分，軟性指派反而勝過只顧第一名的硬指派。

## 新增題型：候選 10 盤、題目 1～5 盤、非一對一

難度完全不同：四分之一的題目只有 1 盤棋，候選人只有 10 盤；同一人可以對應多題，**Sinkhorn 不再適用**。
原本的方法在本地模擬上，1 盤題只有 0.20——**單盤辨識力是瓶頸**。

```
一盤棋 ─→ 逐手特徵（160 手）─→ 7 個逐手序列身分模型（dilated 1D-CNN＋Sub-center ArcFace）
          │                         每個模型：候選的「模板餘弦」＋「同色模板餘弦」→ 各自 z 分數
          │
          └→ 手工特徵 ─→ 度量 MLP ─→ 候選池分類器（600 類，每人 10 盤，L2 1e-4）→ z 分數
                                        │
                     Σ z(序列) ＋ c·z(度量分類器)，除以列標準差
                                        │
                     ＋ λ · 讓先（HD1）標頭似然 / 盤數  ─→ Top-5
```

### 逐手序列身分模型（`scripts/train_seq_identity.py`）

- **輸入**：每盤最多 160 手「我方」的逐手特徵，由幾個特徵庫沿特徵軸串接：
  - `sequences`（12 維）：落子距離、與對手的關係、提子、氣等
  - `seqshape`（12 維）：棋形與手法分類
  - `seqqual`（8 維）：局面判斷品質
  - `seqpatch`／`seqpatch7`（52／100 維，`aicup.movepatch`）：**落子座標**＋落子前 5x5 或 7x7 的我方／對方子
- **網路**：dilated 1D-CNN，8 個殘差塊（寬 192 或 256）→ 256 維 L2 embedding。
- **損失**：Sub-center ArcFace（6,405 個訓練身分、每類 3 個子中心、動態 margin）。
- **挑 checkpoint**：用「新增題型規則」的驗證池（600 候選 x 10 盤、400 題 1／2／3／5 盤）直接量，每 2k 步一次。
- **大資料**：7x7 局部盤面的特徵庫有 16 GB，用 memmap 加兩個背景預讀執行緒訓練，不載入記憶體。

最大的單一發現是**落子座標＋局部棋形**：既有的逐手特徵描述了「這手是什麼手法」，卻沒有「下在哪裡、周圍長什麼樣」；
加上之後單模型就成為最強的成員。

### 分數融合（zfuse）

各序列模型的模板餘弦、度量模型的候選池分類器，尺度完全不同。
每個分數矩陣先在列方向（每題對 600 位候選）做 z 分數再相加；分類器的權重 c 隨序列模型數成比例。
等權串接 embedding、把序列 embedding 餵進分類器，都明顯較差。

### 兩個便宜的個人習慣訊號

- **同色模板**：每位候選分別建「執黑模板」與「執白模板」（另一色以 0.3 的權重收縮進來，因為有些候選某一色只有 0～2 盤）。
  題目的黑棋比黑模板、白棋比白模板。
- **讓先（HD1）似然**：同一位玩家讓先的比例非常穩定（分半相關 0.943）。
  以分色的 Beta-binomial（先驗 0.6／3.0）估計每位候選的 HD1 機率，一題的 log 似然加進最終分數（λ=0.35）。

兩者都在完全沒參與選擇的模擬池上驗證，合計 +0.025；λ 在兩批不同的池上分別掃過、取兩批最佳值之間。

### 集成的演進與飽和

| 序列模型數（＋度量分類器） | 新增的成員 | 增量 |
|---|---|---:|
| 1 | seed 0 | — |
| 2 | seed 2 | +0.011 |
| 3 | ＋seqqual 特徵 | +0.013 |
| 4 | ＋5x5 局部盤面 | **+0.022** |
| 5 | 5x5 局部盤面換 seed | +0.005 |
| 7 | 7x7 局部盤面、全部特徵寬 256（＋同色＋HD1） | +0.035（相對 5 個無同色／HD1） |
| 8 | 7x7＋seqqual、seed 9 | −0.0003 → **飽和** |

### 試過但不採用的方向

| 方向 | 結果 | 原因 |
|---|---|---|
| 逐盤近鄰（取代模板平均） | 明顯較差 | 每人只有 10 盤，逐盤比對雜訊太大 |
| 候選池白化（類內共變異數） | 持平 | 10 盤估不準共變異數 |
| 題目間連結：學一個「兩題是否同一人」的配對分類器再軟合併 | AUC 0.897，但合併後 −0.0006 | 可靠的連結幾乎都是「兩題已經答對」的配對；真正需要幫助的 1 盤題，它的連結最難辨認。完美連結的上限是 +0.12，現有 embedding 做不到 |
| 更多同類序列模型 | 第 8 個 ±0 | 同類模型的資訊重疊 |
| 完整 12k 步的學習率排程 | 比 30k 排程中途的 12k 步差 | 長時間維持高學習率對這個模型比較好；改成 30k 排程、過高峰後停止 |

## 這個子題教會我們的事

1. **最強的身分訊號在開局與「下在哪裡」。** 官方 baseline 跳過前 8 手，等於把最強的訊號丟掉；
   逐手模型加上落子座標與局部棋形之後才真正變強。
2. **全域約束要先量「假設錯了會怎樣」。** 一對一的匈牙利算法在假設成立時最好、錯時最糟；
   Sinkhorn 讓我們在官方確認前就能安全地拿到大部分好處。
3. **集成的增益來自「不同種類的資訊」，不是更多 seed。** 換 seed 的增益很快飽和；
   換輸入（局部盤面）才有大幅進步。
