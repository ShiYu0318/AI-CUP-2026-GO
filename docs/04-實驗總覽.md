# 實驗總覽

這份文件整理整個專案的實驗方法與結論。逐日的完整紀錄（含每一張表與每一個失敗）在 [實驗日誌](RESULTS.md)。

## 量測協定

不同協定量出來的數字不能互相比較。本專案所有數字都遵守：

| 項目 | 規定 |
|---|---|
| 切分 | **player-disjoint**（`make_player_split(meta, val_frac=0.20, seed=42)`）：驗證玩家完全不出現在訓練集 |
| 評估單位 | **題目**，照官方的盤數分布出題；不看單局準確率 |
| 評分 | 官方公式 |
| 重複 | 至少 4 個獨立 seed，回報平均與標準差；比較兩個方法時用**同一批題目的逐 seed 配對差** |
| 校準 | 溫度、切點、融合權重只能在**校準玩家**上擬合，評分玩家必須不重疊 |
| 題數 | 每組至少 800 題（400 題的標準誤約 0.025，差 0.04 以內分不出來） |
| 選擇偏差 | 超參數在一批池上挑，**換一批沒用過的池**確認後才採用 |

賽程後期每一次決策都多加了一條：挑參數用的 seed 池、確認用的 seed 池、最終比較用的 seed 池，三者互不重疊。

### 為什麼不用排行榜調參

排行榜的 public 與 private 各 400 題，標準誤約 ±0.015～0.025；而且兩邊的等級分布不同。
排行榜只用來確認「本地已證明有效的方向」有沒有兌現，從不拿來挑參數。
這條規則救過一次：一個在模擬上預估 +0.02～0.07 的測試集分布對齊，實際上明顯有害——
因為模擬本身就假設了「測試集每級等量」，而那正是被檢驗的命題。

## 判斷一個成分值不值得加

> **它看到了別人看不到的什麼？**

答不出來就只是多一份雜訊。實證：題目層級模型單獨比單局模型差，融合卻有增益，因為它看的是盤與盤之間的變異；
而 LightGBM 與 MLP 吃同一份特徵，只是換函數逼近，融合反而變差。

量化工具是**題目層級**的組內殘差相關。單盤的殘差相關會系統性地高估互補性：
單盤殘差大多是「這盤剛好下好或下壞」的雜訊，聚合成一題後就抵消了；剩下的是玩家層級的共同偏差。

## 成本也要記

每個訓練腳本都把機器時間寫進實驗紀錄（`aicup.experiment_log`）。記下來之後才看得到：**成本與增益幾乎不相關**。

| 實驗 | 訓練分鐘 | 增益 |
|---|---:|---:|
| 玩家辨識：度量學習加入逐手棋形 | 8 | +0.0264 |
| 棋力：序列模型加入棋形 | 170 | +0.0060 |
| 棋力：序列模型改用成對排序損失 | 186 | +0.0018 |
| 棋力：更寬的 MLP | 75 | −0.0031 |
| 棋力：窄而深的序列模型 | 111 | −0.0029 |

## 結論地圖

### 有效（依重要性）

| 子題 | 方法 | 為什麼有效 |
|---|---|---|
| 棋力 | KataGo HumanSL 評我方與**對手**的落子 | 外部知識，不受我們標籤的玩家層級偏差影響；對手反映的是伺服器配對用的評分 |
| 棋力 | 對手視角的手工特徵 | 同上的配對訊號；只用對手甚至比只用我方準 |
| 棋力 | 板面 CNN | 唯一與其他成分誤差負相關的盤面模型 |
| 棋力 | DP 全域最佳切點、均勻先驗校準 | 評分是分段常數；測試集等級分布比訓練均勻 |
| 玩家 | 開局順序特徵 | 最強的身分訊號 |
| 玩家 | 度量學習（Sub-center ArcFace） | 學的是「同一人拉近」，可以推廣到新面孔 |
| 玩家 | Sinkhorn 軟性全域指派（一對一題型） | 一位候選不能同時當很多題的答案；軟性指派在假設不成立時也不會變差 |
| 玩家 | 逐手序列身分模型＋落子座標與局部棋形 | 補上整盤統計看不到的「下在哪裡」 |
| 玩家 | z 分數融合、同色模板、讓先似然 | 不同尺度的分數能相加；兩個穩定的個人習慣 |

### 無效或有害（避免重複投入）

| 子題 | 方法 | 結果 |
|---|---|---|
| 棋力 | 換架構（GBDT、GRU、更寬、更深）做同一份資訊 | 集成已飽和，±0.003 內；同質的高度相關統計量上 MLP 穩定勝過 XGBoost |
| 玩家 | PCA 降維 | 單調變差（16 維 −0.27）：玩家內的局間變異遠大於玩家間差異，PCA 優先保留雜訊方向；監督式投影（度量學習）才是對的 |
| 棋力 | 把玩家辨識的 embedding 當棋力特徵（latent feature） | 有害（−0.09）：ArcFace 被訓練成跨棋力不變，主動壓掉了棋力訊號 |
| 棋力 | 自訓練的棋力條件走法模型 | 單盤強、題目層級 ±0 |
| 棋力 | 落子時間盤面 | 與板面 CNN 同一種資訊 |
| 棋力 | Strength Estimator（ICLR 2025）強度分數 | 題目層級 +0.002 |
| 棋力 | 讓子資訊的統計、stacker 的盤數交互項 | 無增益或變差 |
| 棋力 | 測試集層級的分布對齊、強制每級等量 | 有害 |
| 玩家 | 逐盤近鄰、候選池白化 | 10 盤太少 |
| 玩家 | 學習式題目間連結 | 可靠的連結都在已答對的題目上 |
| 玩家 | 第 8 個同類序列模型 | 集成飽和 |

## 跨子題的教訓

1. **先對照 SOTA 的絕對水準，再做局部最佳化。** 嚴謹的配對證據讓每一步都看起來在進步，
   反而讓人不會懷疑自己在錯的山頭上。最後一週全是 +0.003、+0.0016 這種遞減增益時，就是該停下來重審方向的訊號。
2. **模擬只能驗證「假設成立時」的增益。** 每一個建構出來的驗證集都帶著假設；
   要另外量「假設錯了會怎樣」，並優先選擇在兩種情況下都不會變差的方法。
3. **瓶頸會移動。** 棋力從「解碼」移到「排序品質」再移到「玩家層級偏差」；
   玩家辨識從「特徵」移到「全域指派」再移到「單盤辨識力」。每次移動後，前一階段有效的工具就不再有效。
4. **失敗的紀錄和成功的一樣重要。** 實驗日誌裡有十幾個被否證的方向，每一個都省下了後續的重複投入。
