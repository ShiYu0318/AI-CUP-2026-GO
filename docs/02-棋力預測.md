# 棋力預測（競賽二）

## 架構

```
一題：同一位玩家的 5～20 盤棋（單一執色）
 │
 ├─ 單局 MLP ×5 seed ──────── 手工特徵 589 維 × 我方／對手兩個視角 = 1178 維
 ├─ 題目層級 MLP ×3 seed ──── 同一題各盤特徵的聚合統計（看的是盤與盤之間的變異）
 ├─ 逐手序列 1D-CNN ×2 變體 ─ 每手 24 維（我方＋對手）、48 維（＋棋形）；160 手
 ├─ 板面 CNN ─────────────── 34 層盤面快照 × 每盤 4 個時點，Set Transformer 集合池化
 ├─ KataGo HumanSL（我方）── 5 個棋力 profile 下，我方每一手的人類走法 log 機率
 └─ KataGo HumanSL（對手）── 同上，評對手的落子
        │
        ▼  各成分輸出「這題屬於 10 個等級」的 log 後驗
   學習式 stacker（邏輯迴歸）：log 後驗＋期望等級＋信心＋熵＋log(盤數)
        │
        ▼  期望等級（連續值）
   DP 最佳化切點（在等級均衡的校準集上求全域最佳）→ 10 個等級之一
```

## 各成分與它帶來的資訊

一個成分值不值得加進集成，判準是：**它看到了別人看不到的什麼？**
量化工具是「組內殘差相關」——在每個真實等級內去掉平均後，兩個成分殘差的相關係數，越低越互補。
（直接算 `corr(ev_A − y, ev_B − y)` 是錯的：兩邊都含 `−y`，不管模型好壞都會得到約 +0.6。）

| 成分 | 它看到的東西 | 加入時的配對增益（本地，8 seed） |
|---|---|---:|
| 單局 MLP（我方 589 維） | 整盤的行為、死活、局面品質、落子位置分布、開局順序 | 基礎 |
| ＋對手視角（1178 維） | **對手的表現**：伺服器依等級配對，對手反映的是你的評分，雜訊比你自己這一盤還低 | +0.0507（t=14.8） |
| 題目層級 MLP | 5～20 盤之間的變異 | 單獨比單局模型差，融合卻 +0.0078 |
| 逐手序列 1D-CNN | 「什麼時候發生」：整盤統計會把序盤與官子的同一個錯混在一起 | +0.0237（雙視角） |
| ＋逐手棋形／局面品質 | 手法偏好（接、尖、跳、飛）、愚形、厚薄 | +0.0060 |
| 板面 CNN | 盤面本身；唯一測到與其他成分**誤差負相關**的成分 | +0.0269（t=15.3） |
| KataGo HumanSL（我方） | **外部知識**：在大量人類棋譜上學到的「各棋力的人會怎麼下」 | +0.0294 |
| KataGo HumanSL（對手） | 外部知識 × 配對訊號 | **再 +0.0376（t=12.1）** |

最後兩列是整個專案最重要的發現：**在我們自己的資料上訓練的模型，都卡在同一個玩家層級的偏差上**；
真正能突破的是外部知識（HumanSL），而它和「對手」這個配對訊號相乘時效果最大。

### 手工特徵（`aicup.features`）

整盤 589 維，分成幾族：行為（落子節奏、應手距離）、死活（提子、氣、打吃、棋串數）、
局面品質 7 族、落子位置分布、**開局順序**（前 6 手的折疊 one-hot）、開局轉移幾何與區域造訪順序。
同一套特徵對「對手的手」再算一次，就是對手視角的 589 維。

### 逐手序列（`aicup.moveseq`、`moveshape`、`movequality`）

每一手抽出十幾維的局部描述（與前一手的距離、是否靠近對手、提子、氣、棋形分類、局面判斷品質……），
排成 160 手的序列，餵給 dilated 1D-CNN。推論改成整批而不是逐題後，GRU 版本的推論從 2 小時降到 32 秒。

### 板面 CNN（`aicup.nets`、`scripts/train.py`）

34 層盤面表徵（我方／對方而非黑／白、雙方最近 8 手的盤面、雙方棋串的氣分 4 桶、最近 4 手的位置、執色、手數進度、邊界常數），每盤均勻取 4 個時點的快照，
共用 backbone 抽特徵後用 GeM＋BN-Neck，再以 Set Transformer 把一題的所有快照池化成一個向量。
多任務訓練（棋力的指數軟標籤＋CORN 序數損失＋局面品質輔助 head，各損失依量級動態平衡），160k 步。
玩家身分的 ArcFace head 在程式裡可開，但上線版本的權重為 0。

### KataGo HumanSL（`aicup.humansl`、`scripts/build_humansl_store.py`）

KataGo v1.15 起附帶以棋力為條件的人類走法模型（`b18c384nbt-humanv0`）。
對每一盤棋，在 5 個棋力 profile（8 級、2 級、2 段、4 段、6 段）下查詢**我方每一手**的走法機率（上限 160 手），
取每手平均 log 機率當這盤的特徵；一題的成分 = 各盤加總後正規化的 log 後驗。

幾個實測過的選擇：

| 選擇 | 結果 |
|---|---|
| 每盤評 24 手 → 96 手 | 單盤 Spearman 0.672 → 0.768，最大的單一槓桿 |
| 10 個 profile → 5 個 | 0.768 → 0.775：相鄰 profile 資訊重疊 |
| 加入首選一致率、目數損失 | 有害（小校準集上過擬合） |
| 對數似然取平均（mean）vs 加總（sum） | mean 較好：sum 會讓各 profile 的銳利度差異隨手數放大 |
| 評**對手**的落子 | 與評我方的增益一樣大，而且互補 |

HumanSL 每盤約 7 秒，不可能為驗證集的 20 萬盤全部算；所以改用**固定棋池**校準：
驗證玩家每級 80 位、每人 20 盤，共 16,000 盤。棋池大小的學習曲線在 600 位之後飽和。

## 融合與解碼

**stacker**（`aicup.stacker`）：每個成分的 10 維 log 後驗，加上期望等級、信心、熵與 log(盤數)，
餵進一個邏輯迴歸。它在校準題上擬合，取代人工調的融合權重。

**解碼**：評分有「相鄰一級得 e⁻¹」的部分分，argmax 完全不知道這件事。
做法是把 stacker 的機率轉成期望等級，再用 9 個切點切成 10 級。切點用**動態規劃求全域最佳解**：
官方分數對切點是分段常數的，Nelder-Mead 這類數值最佳化在上面本質是隨機遊走
（同一份資料重跑會在 0.20～0.48 之間跳）。

**切點的等級先驗**：校準集若照訓練的自然分布（A 級最多、1D 最少），DP 會學到「1D 寬度為 0」。
測試集的等級分布比自然分布均勻得多，所以切點在**等級均衡**的校準集上求。

## 試過但不採用的方向

| 方向 | 結果 | 原因 |
|---|---|---|
| 自訓練的棋力條件走法模型（Maia 式） | 單盤 Spearman 0.756，與板面 CNN 相當；加進集成 ±0 | 單盤殘差大多是「這盤剛好下好或下壞」的雜訊；聚合成一題後，剩下的是所有在我們資料上訓練的模型共有的玩家層級偏差 |
| 落子時間盤面（官方 baseline 的 500 通道精簡成 16 通道） | 單盤 0.750，加進集成 −0.0008 | 學到的和板面 CNN 是同一種資訊 |
| Strength Estimator（ICLR 2025）預訓練模型的強度分數 | 單盤 Spearman 0.74；題目層級 +0.002（雜訊內） | 同上：加強的是單盤訊號，題目層級的瓶頸在玩家層級 |
| 讓子資訊 HD 的題目層級統計 | ±0.001 | — |
| 測試集層級的分布對齊（把平均期望等級拉回均勻分布的值） | 明顯變差 | 測試集的等級分布本來就不是精確均勻；偏低是真實的 |
| 每級強制等量的全域指派 | 即使在每級等量的模擬上也只有 +0.0016 | — |
| GBDT 取代 MLP、更寬或更深的序列模型、GRU、成對排序損失 | 都在 ±0.003 內 | 集成在現有資訊上已飽和，限制不是架構也不是容量 |

## 這個子題教會我們的事

1. **先量自己離 SOTA 多遠，再決定要不要繼續局部最佳化。** 賽前一個月的 240 個 commit 都在嚴謹地做小改進，
   直到第一次用論文的指標量自己，才發現差了 30 個百分點——而解法（HumanSL）第一天的方向分析就寫了。
2. **互補性要在題目層級量。** 單盤的殘差相關會系統性高估互補性；走法模型因此白訓練了 26 小時。
3. **剩下的誤差是玩家層級的。** 給一位玩家 5 盤或 50 盤，自訓練模型的準確率幾乎一樣。
   能再進步的只有「外部知識」與「打在玩家層級的訊號」（例如對手）。
