# 工程與重現

## 環境

- Python 3.13、PyTorch 2.10；開發機是 Apple M 系列筆電（MPS），程式自動選 `cuda` → `mps` → `cpu`。
- KataGo v1.18.2（HumanSL 成分需要；macOS 用 `brew install katago`）。
- 套件以 editable 模式安裝，腳本直接 `import aicup`。

```bash
pip install -e ".[torch,dev]"
python3 -m pytest -q                 # 約 480 個測試，先確認環境正常
```

釘死版本的完整依賴在 [`repro/requirements.txt`](../repro/requirements.txt)。

## 資料

資料集不在這個 repo 裡，請自行從競賽頁面與官方 [aicup2026-go-dataset](https://github.com/AILAB-NDHU/aicup2026-go-dataset) 下載，放成：

```
data/
├── training/        train_D.csv … train_6D.csv（官方訓練集 v1.0）
├── tests_rank/      rank_prediction_test_{public,private}.csv
├── tests_player/    player_identification_{test,candidates}_{public,private}.csv
└── v2/tests/        競賽一更新後的測試檔（含 *2_{public,private}.csv）
```

[`repro/data_manifest.json`](../repro/data_manifest.json) 記錄了每個資料檔的 sha256，可用來確認拿到的是同一份資料。
訓練集刻意使用 v1.0：v1.1 只在每盤補上 `HD[n]`，但 HumanSL 的儲存檔以 SGF 原文的雜湊為鍵，換版本會讓鍵全部對不上。

## 建置順序

所有中間產物都在 `cache/`（不進版控）。整條管線在 M 系列筆電上：特徵與序列庫約 1 小時、各模型數小時到一天，
**KataGo HumanSL 是最慢的一步**（每盤約 7 秒；棋池 16,000 盤＋測試集 10,000 盤，我方與對手各一次，合計約 4 天）。

### 1. 共用的特徵庫

```bash
python3 scripts/build_sgf_store.py                         # 全部 SGF 打包成 memory-mapped 檔（多程序共用）
python3 scripts/build_feature_store.py --nproc 10          # 整盤手工特徵 589 維 → cache/features.npy
python3 scripts/build_feature_store.py --nproc 10 --opponent   # 對手視角 → cache/features_opp.npy
python3 scripts/build_shape_features.py                    # 逐手棋形聚合成整盤統計
python3 scripts/build_shape_features.py --opponent

python3 scripts/build_sequence_store.py                    # 逐手序列 12 維 → cache/sequences.npy
python3 scripts/build_sequence_store.py --opponent         # → cache/sequences_opp.npy
python3 scripts/build_sequence_store.py --shape            # 棋形 → cache/seqshape.npy（--opponent 另一份）
python3 scripts/build_sequence_store.py --shape --opponent
python3 scripts/build_sequence_store.py --quality          # 局面品質 → cache/seqqual.npy
python3 scripts/build_sequence_store.py --patch            # 座標＋5x5 局部盤面 → cache/seqpatch.npy（8 GB）
python3 scripts/build_sequence_store.py --patch7           # 座標＋7x7 局部盤面 → cache/seqpatch7.npy（16 GB）
```

### 2. 棋力預測的模型

每個上線模型的完整訓練參數都存在 checkpoint 裡，並匯出到 [`repro/train_args/`](../repro/train_args/)；以下是對應的指令。

```bash
# 單局 MLP（5 seed、1178 維）
python3 scripts/train_rank_mlp.py --extra-features cache/features_opp.npy \
    --seeds 5 --steps 20000 --hidden 1024 --train-games 0 --out cache/rank_mlp_opp_big
# 題目層級 MLP（吃上面的單局模型）
python3 scripts/train_rank_question.py --extra-features cache/features_opp.npy \
    --game-model cache/rank_mlp_opp_big/models.pt --seeds 3 --out cache/rank_question_opp
# 逐手序列 1D-CNN 兩個變體
python3 scripts/train_rank_seq.py --extra-sequences cache/sequences_opp.npy \
    --seeds 3 --steps 16000 --train-games 0 --out cache/rank_seq_opp_full
python3 scripts/train_rank_seq.py --extra-sequences cache/sequences_opp.npy cache/seqshape.npy cache/seqshape_opp.npy \
    --seeds 3 --steps 12000 --train-games 400000 --out cache/rank_seq_shape
# 板面 CNN（160k 步；可分段用 --resume 接續）
python3 scripts/train.py --width 96 --blocks 8 --snapshots 4 --steps 160000 --pool set_transformer \
    --arcface-weight 0 --corn-weight 0.5 --quality-weight 0.3 --balance-losses

# KataGo HumanSL：先建校準棋池（每級 80 位驗證玩家 x 20 盤），再算測試集；我方與對手各一次
export AICUP_HUMANSL_PROFILES=1,3,5,7,9
python3 scripts/build_humansl_store.py --pool --moves 160 --store cache/humansl/games_p5all.jsonl
python3 scripts/build_humansl_store.py --test-dir data --moves 160 --store cache/humansl/games_p5all.jsonl
python3 scripts/build_humansl_store.py --pool --opponent --moves 160 --store cache/humansl/games_p5all.jsonl
python3 scripts/build_humansl_store.py --test-dir data --opponent --moves 160 --store cache/humansl/games_p5all.jsonl
```

### 3. 玩家辨識的模型

```bash
# 度量學習 MLP（8 seed，原題型與新增題型共用）
python3 scripts/train_feature_metric.py --seeds 8 --steps 12000 --hidden 1024 \
    --extra-features cache/features_opp.npy cache/features_shape.npy cache/features_shape_opp.npy \
    --out cache/feature_metric_h1024s12k

# 逐手序列身分模型：30k 步排程、每 2k 步用新增題型的驗證池評估、過高峰後停止
T="python3 scripts/train_seq_identity.py --steps 30000 --eval-every 2000 --stop-after-peak 10000"
$T --seed 0 --out cache/seq_identity
$T --seed 2 --out cache/seq_identity_30k_s2
$T --seed 3 --stores cache/sequences.npy,cache/seqshape.npy,cache/seqqual.npy --out cache/seq_identity_30k_s3q
$T --seed 5 --train-games 500000 --stores cache/sequences.npy,cache/seqshape.npy,cache/seqpatch.npy --out cache/seq_identity_patch
$T --seed 6 --train-games 500000 --stores cache/sequences.npy,cache/seqshape.npy,cache/seqpatch.npy --out cache/seq_identity_patch_s6
$T --seed 7 --mmap --stores cache/sequences.npy,cache/seqshape.npy,cache/seqpatch7.npy --out cache/seq_identity_patch7
$T --seed 8 --mmap --width 256 \
   --stores cache/sequences.npy,cache/seqshape.npy,cache/seqqual.npy,cache/seqpatch7.npy --out cache/seq_identity_all256
# 每個輸出夾的 best.pt 是驗證分數最高的 checkpoint；上線版本複製成 stepXXXX.pt（見 repro/models.tsv）
```

### 4. 產生預測

```bash
# 棋力（＋原題型的玩家辨識）；--check 先確認所有依賴都在
python3 scripts/predict.py --check --test-dir data --humansl --humansl-opponent --humansl-store cache/humansl/games_p5all.jsonl
AICUP_HUMANSL_PROFILES=1,3,5,7,9 python3 scripts/predict.py --test-dir data \
    --humansl --humansl-opponent --humansl-store cache/humansl/games_p5all.jsonl \
    --pool-classifier --out-dir out/

# 玩家辨識（新增題型；原題型的列沿用上一步的輸出）
python3 scripts/predict_player_v2.py --old out/submission_player.csv --test-dir data/v2/tests \
    --method zfuse --fuse-c 0.2 --same-color --hd-lambda 0.35 \
    --seq-identity cache/seq_identity/step12000.pt cache/seq_identity_30k_s2/step14000.pt \
        cache/seq_identity_30k_s3q/step12000.pt cache/seq_identity_patch/step12000.pt \
        cache/seq_identity_patch_s6/step12000.pt cache/seq_identity_patch7/step16000.pt \
        cache/seq_identity_all256/step12000.pt \
    --out out/submission_player_v2.csv
```

兩支腳本寫檔前都會跑完整的官方格式驗證（題數、前綴、Top-5 不重複且都在對應的候選池），驗證不過就不寫檔。

## 重現性紀錄（`repro/`）

[`repro/`](../repro/) 讓每一份輸出都能在另一台機器上重新產生：

| 檔案 | 內容 |
|---|---|
| `requirements.txt` | 原始碼實際 import 的第三方套件（AST 掃描），版本釘死 |
| `models.tsv` | 每個上線 checkpoint 與外部模型的 sha256、大小、用途、來源 |
| `train_args/*.json` | 直接從權重檔取出的訓練參數（不靠記憶或文件） |
| `data_manifest.json` | 資料檔的 sha256 與整體指紋 |
| `recipes/*.json` | 每一份輸出的完整指令、commit、資料指紋、模型雜湊與輸出雜湊 |

除 `recipes/` 外都由 `scripts/build_repro.py` 產生。

## 工程上的幾個決定

**分層**：`src/aicup/` 是可匯入的函式庫，定義「什麼是正確的」——評分公式、棋盤規則、切分協定、模型結構，沒有 CLI；
`scripts/` 是可執行的流程，每支做一件事。依賴是單向的：`src/` 從不 import `scripts/`，
`tests/test_layering.py` 會擋住這條界線（它曾經漂移過一次：模型定義住在訓練腳本裡，害得推論腳本依賴訓練腳本）。

**量測協定寫死在程式裡**：題目層級、player-disjoint、官方盤數分布、校準與評分的玩家不重疊。
`aicup.benchmark` 出題、`aicup.scoring` 算分，所有評估腳本共用。

**OOF 後驗快取**（`aicup.oofcache`）：題目層級的後驗帶三重指紋——checkpoint 內容雜湊、題目集雜湊、語意版本。
換模型不會拿到舊後驗，融合實驗從 20 分鐘變成秒級。

**自駕實驗迴圈**（`scripts/auto_loop.py`）：跑實驗 → 用固定協定 gate → 記錄 → commit → 下一個。
gate 的「尺」有版本號，換定義時自動作廢舊基準——文件擋不住這種錯，機制可以。

**測試釘住「不會報錯的錯」**：評分公式的邊界、棋盤提子的不變量（盤上子數＋被提子數＝總手數，對真實棋譜驗證）、
切分互斥性、訓練與推論的張量尺度一致、每一條會讓提交作廢的格式規則。

**不會靜默降級**：任何一盤缺 HumanSL 特徵、任何成分集合與校準時不同，推論直接中止並印出補算指令。

## 在筆電上跑長時間工作的教訓

| 事件 | 教訓 |
|---|---|
| KataGo 分析引擎沿用範例的 `nnCacheSizePowerOfTwo = 23`，快取長到 11 GB，swap 用到 34 GB，另一個訓練 2,000 步卡了 12 小時 | 開跑前先看設定裡任何「隨使用量成長」的參數，第一個小時量一次記憶體。我們的查詢每個局面只用一次，快取改成 2^17 後穩定在 1.8 GB |
| DataLoader 每個 worker 各自載入全部 CSV（約 3 GB），多開幾個就把機器吃光，而且是**安靜地**停住 | `--workers` 留 0，或先把 SGF 打包成共用的 memory-mapped 檔 |
| 16 GB 的局部盤面特徵庫載入記憶體會讓機器開始 swap | 訓練端走 memmap＋兩個背景預讀執行緒（各自不同的隨機種子，避免重複的 batch） |
| 組裝大型特徵庫時先串接再寫檔，記憶體峰值是兩倍 | 逐檔寫進預先配置好的 memmap |
| 停背景工作時 kill 了管線前端，Python 本體一直留著 | kill 工作自己的 PID，不要 kill 管線 |
| 筆電闔蓋或改用電池時睡眠，長時間訓練停擺數小時 | `caffeinate` 只擋得住閒置睡眠；長時間工作要接電源、不闔蓋 |
| 系統的 Python 被套件管理器升級，路徑消失 | 重現紀錄記下確切的 Python 版本；評估重跑得到完全相同的數字，結果不受影響 |
