# 未來方向

賽程結束時，兩個子題都撞到了同一種牆：**在自己的資料上換模型、加成員已經擠不出東西**。
這裡記下有算力時最值得做的事，以及背後的依據。

## 已知的瓶頸

| 子題 | 瓶頸 | 證據 |
|---|---|---|
| 棋力 | 玩家層級偏差：玩家的標籤等級與他實際下出來的水準之間的落差 | 給自訓練模型 5 盤或 50 盤，準確率幾乎一樣；單盤更強的訊號（SE、走法模型）在題目層級增益趨近 0 |
| 玩家辨識（1～5 盤題） | 單盤辨識力 | 1 盤題約 0.40、5 盤題約 0.85；同類序列模型在 7 個時飽和 |

## 一、以預訓練圍棋主幹的逐手 embedding 為輸入（兩個子題共用）

現有的逐手特徵是人工設計的十幾維描述。KataGo HumanSL（`b18c384nbt-humanv0`）在大量人類棋譜上學過
「各棋力的人會怎麼下」，它的主幹特徵對局面與落子的理解遠比手工特徵豐富。
公開專案 KataRank 的對照顯示，用 KataGo 主幹 embedding 接 set transformer，明顯勝過只用十幾維純量特徵。

1. **特徵快取**：凍結 HumanSL 主幹，對每一手抽出落子點的特徵與全盤池化特徵（降到約 64 維、float16 memmap），
   外加多個棋力 profile 下實戰手的 log 機率。100 萬盤約 2.5 億個局面，原樣儲存約 190 GB，所以一定要降維。
2. **棋力模型**：逐手 transformer（我方與對方的手交錯輸入、加執色 embedding）→ attention 池化成盤向量 →
   set transformer 跨 5～20 盤聚合。訓練題依玩家抽樣、玩家均衡、單一執色、排除讓 2 子以上，與測試結構一致。
   損失直接對齊評分（正確 1、相鄰 e⁻¹ 的軟標籤）＋序數 head。
3. **身分模型**：同一份逐手特徵＋局部盤面 → transformer → 盤向量；Sub-center ArcFace ＋ 直接模擬
   「10 盤候選、1～5 盤題目」的 episodic loss。
4. **端到端微調**：解凍主幹最後幾個 block，補回降維丟掉的資訊。

依據我們自己的實驗，最值得盯的指標是：棋力的 2D／3D 完全正確率（目前最弱的兩級），以及玩家辨識的 1 盤題分數。

## 二、玩家辨識：在候選池上做測試時微調

目前所有序列模型推論時都是凍結的，只拿來算模板相似度。候選池（600 人 x 10 盤）本身就是一份有標籤的資料：
以候選人為類別，對每個序列模型做短時間微調，讓 embedding 適應這批新面孔。
它改變的是表示本身，不是在既有分數上疊加，所以不受「集成已飽和」限制。
風險是每人只有 10 盤，必須嚴格控制步數，並在模擬池上驗證。

## 三、棋力：打在玩家層級偏差上的訊號

在我們資料上，能突破玩家層級偏差的只有兩種東西：外部知識（HumanSL）與配對訊號（對手）。
沿這個方向還沒做完的：

- 對手的**主幹 embedding**（不只是 log 機率），與我方的交互作用；
- 同一題內各盤之間的一致性（同一玩家在不同對手、不同局面下的表現差異）。

## 不建議的方向

- **每人一個個人化走法模型**：每人只有 10 盤遠不夠；文獻中這類方法在西洋棋上也明顯輸給 embedding 法。
- **再加同類的單盤模型或同類序列模型**：我們已經量到兩個子題都飽和。
- **在測試集上做分布層級的對齊**：沒有可靠的方法驗證分布假設，實測有害。
